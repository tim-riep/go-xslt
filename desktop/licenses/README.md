# Third-party licenses: one source, everything else generated

Do not edit `NOTICE`, `THIRD-PARTY-LICENSES.md`, `licenses_gen.go`,
`desktop/LICENSE` or anything under `go/`, `npm/`, `project/` here. They are
generated by

    go run ./scripts/licenses          # regenerate (from anywhere in the repo)
    go run ./scripts/licenses -check   # verify, change nothing (CI job `licenses`)
    go run ./scripts/licenses -v       # also print the Go modules found per target

## The single source

| Input | What it says |
|---|---|
| `go list -deps` per release target | Which Go modules are compiled in. Library `./...` and the desktop main package, for darwin/windows/linux x amd64/arm64, with and without `-tags production`; the union is documented. Each module's license file is read from the module cache. |
| `desktop/frontend/package-lock.json` + `node_modules` | The npm production tree (every package without `dev: true`). License id from `package.json`, text from the package's license file. Needs `npm ci` first. |
| `extra.json` (hand-kept, documented at its top) | What no manifest knows: the project itself, the Go standard library, the Unicode data behind `internal/xpath/regex_blocks_ucd.go`, the Sun/FreeBSD notice on the `math.Exp` copy in `internal/xpath/exp.go`, the Inter font, and the upstream texts of npm packages that ship none. |
| `data/`, `fonts/` | The hand-kept texts `extra.json` names. A file there that nothing names is an error. |

Outputs: the texts under `go/`, `npm/`, `project/`; `licenses_gen.go` (the
list behind the app's Licenses view, `LicenseService`); `../../NOTICE`;
`../../THIRD-PARTY-LICENSES.md` (also attached to every release, for CLI
users who have no Licenses view); `../LICENSE` and the license file beside the
bundled font (`frontend/public/Inter-Medium.LICENSE.txt`), so copies never drift.

## What `-check` fails on

- a generated file differs from the committed one, is missing, or a stale file
  sits in a generated directory (a dependency was added, bumped or removed
  without regenerating: this is how the missing `@codemirror/lang-json` would
  have been caught);
- a shipped dependency has no license file, or a text no rule recognises, or two
  rules claim it, or the `package.json` licence field disagrees with the text;
- the detected license is not on the allow-list (MIT, BSD-2-Clause,
  BSD-3-Clause, Apache-2.0, ISC, OFL-1.1, Unicode-3.0, 0BSD, Unlicense). A
  new one fails until a human has read it and added it to `allowed` in
  `scripts/licenses/detect.go`;
- `extra.json` and the hand-kept files disagree (declared id vs. text, orphan
  text, override for a package no longer shipped).

## Adding something that is not a dependency

Embedded third-party data, copied code, a bundled font or image: add a
component to `extra.json` with its text under `data/` (or `fonts/`), then
regenerate. If its text must travel in full, set `"notice": true`.

## Notes

- npm packages without a license file in their tarball: the three `@uiw/*`
  packages and `@wailsio/runtime` (all declare MIT). Their upstream
  repository's LICENSE is kept under `data/npm/` and named in `npm_texts`;
  it is used only because the package ships none.
- Listing the desktop module for linux and darwin needs no C toolchain:
  `go list -e -deps` does not run cgo, a compiler or pkg-config (with
  `CGO_ENABLED=1` it keeps the cgo files, so the Linux-only D-Bus dependency
  is seen). A missing `frontend/dist` (go:embed) is a reported package error,
  tolerated by `-e`. CI needs only Go and, for the npm side, `npm ci`.
- The Unicode License v3 text in `data/unicode/LICENSE` was written from the
  published license (unicode.org/license.txt was not reachable when it was
  added); compare it with the live text when convenient.
