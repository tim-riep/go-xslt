XSD 1.0 / 1.1 conformance — progress log
========================================

Harness:  test/conformance/xsd_test.go  (TestXSD)
Suite:    W3C XML Schema Test Suite (github.com/w3c/xsdtests, local-only clone
          at test/conformance/xsdtests/, gitignored). Verdict-only oracle:
          each <schemaTest>/<instanceTest> asserts valid|invalid.
Engine:   internal/xsd  (from-scratch, pure Go). Public API: engine.Validate.

Run (compiled binary, live progress):
  go test -c -o /tmp/conf.bin ./test/conformance/
  cd test/conformance && XSD_PROGRESS=1 /tmp/conf.bin -test.run=TestXSD -test.v
  Knobs: XSD_ONLY=<set-substring>  XSD_VERSION=1.0|1.1  XSD_SEQ=1

Denominator = applicable schemaTest + instanceTest cases per version (a testGroup
or <expected> may carry version="1.0|1.1"; absent = both). "unsupported" = the
validator returned ErrUnsupported (could not decide) — neither pass nor fail, so
the baseline is honest.

Implemented: a minimal schema loader (global element decls + named simpleTypes;
restriction/list/union; anything else ⇒ ErrUnsupported so no wrong verdicts), the
facet subsystem (pattern via xpath.CompileRegex anchored, enumeration by value,

(xsi:nil/xsi:type, no-child / no-attr checks).

Key triage wins this milestone: length family gated to applicable types (QName/
numeric length ⇒ always-satisfied per the suite); a restriction of a list/union
inherits that variety so its facets bound the whole list/union; patterns our
XSD→RE2 translator can't render (\i/\c in class-subtraction) ⇒ ErrUnsupported, not
a false "invalid".

  was used, so redefine instances FP'd on "content does not match"). Now each

  now accepts a derived particle that matches only empty (matchesOnlyEmpty), (b) a
  lenient recurseSeq fallback (tried ONLY after the strict one-to-one mapping
  fails, so it can never reject what strict accepted) lets a repeatable base
  wildcard absorb a run of derived particles whose SUMMED occurrence fits the
  wildcard's — recovers the particlesHa "multiple particles restrict a repeatable
