go-xslt 0.4.2 is a performance release: three more measured rounds on the engine, judged on the whole engine, with every W3C conformance number the same as in 0.4.1.

## Engine

- **A committed A/B harness decides every performance change.** `go run ./scripts/perfab -a <rev> -b <rev>` measures two builds on 23 workloads (XSLT 1.0 and 3.0 transforms, XSD 1.0/1.1 validation, keys, regex, strings, numbers, `xsl:number`, deep recursion, HTML and JSON output, streaming, compile-only, many small runs), alternating, and accepts a change only when no workload gets slower, allocates more, uses more memory or executes more instructions (`-ir` counts instructions under cachegrind, deterministic on a noisy machine); outputs must stay byte-identical.
- **`xsl:number`** builds one match context per evaluation instead of one per candidate node: numbering a 2,000-record document with `level="single"` and `level="multiple"` took 4.2 s of CPU and 3.5 GB of allocations, now 0.4 s and 8 MB.
- **`array(T)` parameters** checked on every `xsl:iterate` step remember the members already verified, so an accumulating array is no longer re-checked in full each step: 8.2 s → 0.2 s on 20,000 records.
- **XSD 1.1 validation** allocates 20 % less: the per-element assertion tree comes from two slabs with one annotation table, and identity constraints no longer build a content-model map per selected node.
- **Fewer allocations across the engine**: the streaming reader builds an element and its attributes in one allocation (8 % fewer allocations when streaming); `string-join`, `normalize-space`, case mapping, the regex functions (the zero-length-match check once per pattern), `format-date`/`format-time`/`format-dateTime`, the serializer's indentation and `json-to-xml` allocate less (6 % fewer allocations on string-heavy and JSON workloads, 7 % on a transform made of function calls); a single typed value is type-checked without boxing it; the static base URI is computed only when a function needs it instead of before every expression; node sets pass through `subsequence`, type checks, one-item output and `current-group()` without boxing (a 5,000-deep recursive template needs 30 % less memory; many small transforms allocate 9 % less).
- Measured on the whole 23-workload set against 0.4.1, no workload executes more instructions; peak memory and allocated bytes are at or below 0.4.1 on every workload.
