go-xslt 0.4.3 is a performance release: six more measured rounds on the engine, in two parallel tracks, judged on the whole engine with the same rule as 0.4.2 — no workload may get slower, allocate more, use more memory or execute more instructions, and every output stays byte-identical. Every W3C conformance number is the same as in 0.4.2.

## Engine

- **Streaming reads with the engine's own tokenizer.** The streaming reader used `encoding/xml`, which allocated for every token; it now runs the parser's own tokenizer over a 64 KB window of the input, with every token delivered whole and the memory bound unchanged (0.3 MB peak heap for an 82 MB document). Streaming the 200,000-record document: 59 % fewer instructions, 76 % fewer allocations, 49 % less CPU time.
- **JSON** is tokenized in place when the text is valid (an invalid text still gets `json.Decoder`'s error): the JSON round trip executes 41 % fewer instructions and makes 46 % fewer allocations.
- **Compiling a stylesheet** parses each secondary module once, not twice, and copies lists only where it changes them: compiling DocBook's `docbook.xsl` executes 32 % fewer instructions and allocates 38 % less.
- **XSD 1.1 validation**: the assertion tree of every element comes from one arena the validation call keeps, identity constraints reuse one evaluation context and build key tuples in one buffer, assertion operands are atomized without one-item sequences, and the typed-value casts reuse cached small integers and build plain decimals from an int64 mantissa. Validating the 200,000-order document: 25 % fewer instructions, 62 % fewer allocations, 68 % less allocated, 44 % less CPU time.
- **xsl:number** passes its node tests by pointer and decides once per evaluation what its count pattern needs: numbering with position()/last() executes 31 % fewer instructions.
- **Function calls and variables**: a template or function frame keeps its bindings in a short slice instead of a map, the callee's scope stack reuses the caller's spare capacity, the matching context for a declared type is remembered per run, a path's node set travels unboxed into predicates, comparisons, built-in arguments, selects and tests, the arguments of the string and number built-ins live on a per-run stack, and `concat`/`string-join` build their result in one allocation. The function-call workload: 31 % fewer instructions, 52 % fewer allocations; deep recursion: 19 % fewer instructions.
- **Parser and serializer**: an unprefixed name is resolved from a default-namespace stack, one frame per open element, positions looked up only where needed; the serializer decides the HTML version and XML 1.1 once and mirrors the default namespace beside its prefix map. Copying the 37 MB document: 15 % fewer instructions; HTML output: 22 % fewer instructions, 34 % fewer allocations.
- **Maps and iteration**: a map key keeps its category beside its string instead of a prefixed copy, `xsl:next-iteration` hands its values on in a slice and compares errors without a panic per iteration, `for` loops and the simple map operator reuse one evaluation context per loop. Iterating over maps: 20 % fewer instructions, 25 % fewer allocations.
- Measured on the whole 23-workload set against 0.4.2 (`go run ./scripts/perfab -a v0.4.2 -b v0.4.3`, 8 alternating runs, then `-ir`): every workload executes fewer instructions (between 8 % and 59 % fewer) and takes less CPU time (between 6 % and 49 % less); peak memory and allocated bytes are at or below 0.4.2 on every workload; every output is byte-identical. The candidates that were tried and rejected are documented on the performance page.

## Build

- The binaries are built with **Go 1.26.11**, which fixes GO-2026-6859 (an HTTP/1 server crash in `net/http`). The library itself still needs only Go 1.25.
